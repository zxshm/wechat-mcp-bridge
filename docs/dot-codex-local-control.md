# dot 读取并接续本地 Codex 对话

微信可以作为接续本地 Codex 任务的入口。用户在微信里提出任务、补充要求或请求查看进度，中继端把真实来信交给 dot。dot 使用客户端原生工具读取目标对话，将请求转达给该已有对话，再回读执行结果。

## 已验证的工作方式

1. 用户指定已连接的电脑及已有 Codex 对话。
2. dot 调用 `read_thread`，取得对话标题、项目路径、近期轮次与当前状态，核对目标。
3. dot 调用 `send_message_to_thread`，把用户授权的任务或补充要求交给同一个对话。
4. 本地对话接续已有上下文和项目工作，实际处理请求。
5. dot 再次调用 `read_thread`，核对目标实际回应，并通过已绑定微信连接交付结果。

本次 GitHub 文案更新也通过这条路径转达。先发送原更新要求，随后发送“突出介绍本地 Codex 对话接续能力”的补充要求，两条消息均进入同一个正在处理任务的 Windows 对话。

## 组件职责

| 组件 | 负责的工作 |
| --- | --- |
| 微信中继端 | 接收本人微信来信、发布事件、执行微信发送、保存队列和交付附件 |
| dot | 理解用户请求、识别目标任务、调用原生工具、回读和交付结果 |
| 客户端原生对话工具 | 提供对已连接电脑上 Codex 对话的读取和请求转达 |
| 本地 Codex 对话 | 使用原上下文及项目环境接续执行任务 |

微信中继端当前实现部署在 Linux 上。2026 年 11 月 15 日的原生对话控制验收在 Windows 上完成。这两部分可以分别运行在用户选择的中继主机与工作电脑上。

## 原生工具调用示例

下面的工具名以客户端提供的正式能力为准，部分环境会显示命名空间前缀。`hostId` 和 `threadId` 应取自当前设备及目标对话的真实发现结果。

先读取目标并核对返回的标题、路径和近期状态。

```javascript
await tools.read_thread({
  hostId: 'local',
  threadId: targetThreadId,
  turnLimit: 1,
  includeOutputs: false
});
```

用户授权转达后，向同一已有对话发送清晰的任务要求。

```javascript
await tools.send_message_to_thread({
  hostId: 'local',
  threadId: targetThreadId,
  prompt: '请接续当前项目任务，更新公开介绍中的术语，并回报实际提交结果。'
});
```

随后再次读取同一目标，核对实际回应。发送时省略模型和推理强度覆盖参数，沿用目标对话现有设置。运行中的对话可以接收补充要求并继续当前任务。

## Windows 实测记录

以下为 2026 年 11 月 15 日同一已有 Windows 对话的当次验收样本，时间采用 UTC+8。

| 操作 | 实际结果 | 当次耗时 |
| --- | --- | --- |
| 读取已有对话 | 标题、路径和本地主机均匹配 | 7.054 秒 |
| 向该对话发送测试请求 | 返回成功，目标对话实际收到并回应 | 9.037 秒 |
| dot 回读目标实际回应 | 文本与回应消息编号均匹配 | 1.451 秒 |
| 官方工具脚本恢复后的再次读取 | 同一目标读取成功 | 1.405 秒 |

测试中的目标对话保持运行，接收到请求后给出确认。dot 回读了该确认，本机独立读取也得到同一回应。这一验证覆盖了读取、转达、接续和结果回读。

## 运行条件

控制本地 Codex 对话需要目标电脑在线、桌面应用运行、dot 已获准访问该电脑，以及当前执行环境提供可用的原生工具。写入请求遵循用户授权与客户端正常权限。具体操作能否完成，还取决于目标对话的执行环境和工具能力。

文字与文件同步可以在云端和中继端之间持续运行。本地 Codex 任务使用工作电脑上的运行环境，接续该任务时需保持这台电脑可连接。

当前公开记录包含 Windows 原生对话验收。其他操作系统可依据客户端当前支持情况，在自己的设备上完成同样的读取、发送和回读验证。[官方连接电脑说明](https://learn.chatgpt.com/docs/dots/computers-and-apps)
